# 從零打造 FPGA 觸控螢幕：一場 24 個版本的逆向工程實錄

> 這篇文章記錄一個真實的工程問題：如何在一塊沒有作業系統、官方驅動又被鎖死的 FPGA 開發板上，讓一片電容式觸控螢幕真正「知道你摸了哪裡」。
>
> 它不是事後美化的成功故事。從第 1 版到第 24 版，中間走過好幾條最後證明是錯的路——猜錯位址猜了 15 版、把官方 Linux 驅動當聖經結果完全沒用、連 AI 自己都判讀錯波形、還建議了該被打臉的解法。**這些錯誤本身就是內容**，因為逆向工程真正的樣子就是這樣。
>
> 我會盡量讓一開始什麼都不懂的人也能讀懂：每個專有名詞第一次出現都先用白話解釋。

---

## 給新手的背景知識速成班

先建立五個概念，後面就跟得上。

### 1. FPGA 是什麼？跟寫程式有什麼不同？

寫程式（Python、C）是寫一串「指令」交給 CPU 一行行執行；CPU 是別人造好的固定晶片。**FPGA（場域可程式化邏輯閘陣列）不一樣**——它是一塊「可以重新接線」的晶片，你用 **Verilog** 語言描述的不是指令，而是**電路本身**：哪條線接到哪、什麼訊號在第幾個時脈變化。寫完之後，FPGA 內部真的會長出你描述的那個電路。

關鍵差異：在電腦或手機上，作業系統早就準備好觸控螢幕的驅動，你不用管底層。但**裸的 FPGA 上沒有作業系統、沒有人幫你寫驅動**，要讓觸控動起來，你得親手用電路「敲」出和觸控晶片溝通的每一個訊號。這就是為什麼這件事這麼難。

硬體：**Terasic DE2-115**（核心是 Cyclone IV EP4CE115F29，系統時脈 50MHz），插上 **VEEK-MT 觸控螢幕**（800×480）。

### 2. 觸控螢幕怎麼知道你摸了哪裡？

電容式觸控的玻璃面板只是一片感應電極，**它不會自己算座標**。真正負責「把電容變化換算成 X/Y」的是一顆獨立的小晶片，叫**觸控控制器**。這次的型號是 **Cypress CY8CTMG120-56**——而且這顆型號是**拆開螢幕、看晶片上的絲印確認**的，不是用猜的。它是一顆 **PSoC（可程式晶片，內含微控制器）**，這個「它有大腦」的特性後面會反覆作怪。

整條鏈：你的手指 → 玻璃感應到電容變化 → Cypress 晶片算出座標 → **FPGA 把座標讀回來** → 後續邏輯使用。我們要解決的就是中間那一段：**FPGA 怎麼跟 Cypress 晶片講話、把座標問出來。**

### 3. I2C：兩條線的對話

FPGA 和觸控晶片用 **I2C** 協定溝通。只要記住：

- 它只用**兩條線**：**SDA**（傳資料）和 **SCL**（傳時脈節拍，像節拍器決定「現在這一拍看資料」）。
- 有主從之分：**FPGA 是主機（master）**負責發起，**觸控晶片是從機（slave）**被動回答。
- 每顆從機有一個**位址（address）**，像門牌。**具體來說，這個門牌就是一個 7 位元的數字**（0x00～0x7F，也就是 0～127）：主機發起對話後送出的第一個位元組，前 7 個 bit 是位址、最後 1 個 bit 表示「這次要寫還是要讀」（0=寫、1=讀）。喊對門牌，對應晶片才理你——它會在第 9 拍把 SDA 拉低一下表示「我收到」，這叫 **ACK**；沒拉低就是 **NACK（沒人理）**。

這個「位址」會是整個故事最大的坑。

### 4. 中斷線（INT）：一條「我有事」的專線

除了那兩條線，觸控晶片還拉出一條 **INT（中斷線）**：有手指碰螢幕時，它把這條線拉低，等於說「現在有人在摸我」。記住它，後半段的主角就是它。

### 5. 你的眼睛：SW、HEX、LEDG 三個觀察窗口

FPGA 裸機沒有主控台、不能 `print` 變數。整個除錯過程，**人能看見晶片內部狀況的唯一窗口，就是板子上這三樣**——而且全是親手撥、親眼看、再整理成文字回報的：

- **SW（指撥開關）**：板上一排實體小開關（SW0～SW17），可手動往上（=1）或往下（=0）撥，用來**現場切換測試選項**，不必每次重編譯。
- **HEX（七段顯示器）**：8 個十六進位數字管（HEX7…HEX0），把讀回來的位元組／數值秀成 16 進位給人看。
- **LEDG（綠色 LED）**：板上一排綠燈（LEDG0、LEDG1…），當**狀態指示燈**用（亮／滅／閃）。

一個關鍵提醒：**這些都是除錯版，同一顆開關或同一顆燈在不同版本代表完全不同的東西**（這版 SW0 是「速度」、下一版可能變成「位址」）。所以下面每次用到，我都會註明它「當下」的意思。

## 貫穿全程的方法論

這趟旅程一直在重複同一個迴圈，本質就是科學方法用在除錯上：

1. **觀察現象**——螢幕現在到底發生什麼？
2. **提出可被否證的假設**——不是「應該哪裡怪」，而是「我猜是 X；如果是 X，做 Y 就會看到 Z」。重點是這假設要能被一個實驗推翻。
3. **查資料**——規格書、官方原始碼、論壇案例。
4. **設計最小實驗驗證**——改動越小越好，一次只動一個變因。
5. **看證據下判斷**——符合就保留，不符就**推翻、回頭重查**，提新假設。
6. 回到第 1 步。

這套迴圈，這個專案跑了至少二十幾輪。底下按真實時間線一段段走。還有一個貫穿全程的人定原則：**「能用理性 + 免費工具解決就不花錢」**——所以後面用的是 Quartus 內建的免費邏輯分析儀，而不是去買實體設備。

## 第一關：上鎖的大門（為什麼非得自己寫）

**現象：** 想讓觸控動起來，最自然的念頭是用現成的驅動（硬體界把這種別人寫好的模組叫 **IP**，智慧財產核心）。但使用者手上那份 `i2c_touch_config.v` **打不開、不能用**。

**逐一排查後，每一條「拿現成驅動」的路都是死的：**

1. 使用者手上那份檔案打開是一堆二進位亂碼——它**本身損壞了**（很可能是從光碟複製或解壓時出錯）。
2. 光碟裡的官方版本是**加密的 IP**，看不到原始碼。
3. 要解密得有 **license，但所有授權檔都失效**。
4. 燒在板子上、學長那份**會動的程式**鎖在 EPCS（板上儲存設定檔的快閃記憶體）裡，而 **bitstream**（編譯後燒進 FPGA 的設定檔）**不能反編譯回 Verilog**。
5. 確認晶片是 CY8CTMG120 後上網找——但 **Terasic 的客製韌體（KOR 碼）沒有任何公開的時序/格式文件**。

**決定：** 既然每扇門都鎖死，那就**從零自己寫 I2C 驅動**——靠 **SignalTap**（Quartus 內建、免費的邏輯分析儀）直接看真實波形，照著波形刻。SignalTap 的角色像在電路內部裝一台示波器，能把晶片實際運行時的訊號波形抓出來看。選它而不買實體邏輯分析儀，正是「免費 + 理性」原則。

> 給新手的話：當一條路被證實走不通，正確反應是**換一條更底層、更可控的路**，而不是反覆敲鎖死的門。

## 第二關：第一次通訊，與 SDA/SCL 的競態（v1–v9）

要跟 I2C 晶片講話，第一件事是喊對門牌。前面說過，這個門牌具體是一個 **7 位元數字**；主機把它**左移一位、在尾巴補上那個「讀/寫」位元**，湊成一個位元組送上線。所以同一個門牌在線上會有兩種長相——以後面確定的真值 **0x08** 為例，它實際送出的位元組是 **0x10（寫）/ 0x11（讀）**；而一開始誤用的 **0x24**，送出的是 **0x48（寫）/ 0x49（讀）**。

但這個門牌一開始就被各種假情報帶偏：最早甚至以為晶片是 SSD2533，接著猜 MTL 的 0x15，最後依交接文件用 **0x24**。（0x24 還藏著一個經典陷阱：I2C 位址有「7 位元」和「含讀/寫位元的 8 位元」兩種寫法。如果當初那個掃描器報的是 8 位元的 0x24，真正的 7 位元門牌其實是它的一半 **0x12**——光是這兩種表示法搞混，就足以讓你一直敲錯門。）這個 0x24 會一路錯到第 15 版。

**現象（v1～v8）：** 不管怎麼讀，回來都是 0x00 或 0xFF（垃圾值）。（這串在 HEX 上顯示成 `FF0000FF`——前兩位是讀到的第一個位元組、後兩位是第二個位元組、中間 `0000` 只是分隔；所以「全 FF」看起來就是這個畫面，也是後面一再出現的那串。）

**v8 的真 bug（靠 SignalTap 逐行比對抓到）：** 送一個 bit 時，`sda_o` 和 `scl<=0` 在同一拍設定，造成 **SDA 在 SCL 還沒穩定變低時就變動**——這違反 I2C 鐵律「SCL 高電平時 SDA 必須穩定」，於是 slave 把它誤判成 START/STOP 訊號，整個對話亂掉。

**v9 修正：** 改用嚴謹的 **5-phase bit 時序**（phase0 設 SDA → phase2 拉高 SCL → phase3 取樣 → phase4 落下），嚴格保證 SDA 只在 SCL=0 時變動。波形顯示整個傳輸流程乾淨了，結構完全正確。

**但 v9 帶出新謎：** slave **ACK 了讀取位址**（它在線、認得請求），可是進入資料階段就**完全不驅動 SDA**，讀回來全是 FF。怎麼確定它「沒在送」而不是「我沒讀到」？看**接收用的移位暫存器** `sh_rd`（負責把線上一個一個 bit 收進來、湊成一個位元組）的變化：`00 → 01 → 03 → 07 → 0F → 1F → 3F → 7F → FF`。這是「每個時脈往左推一格、塞進一個 1」的軌跡——代表每一拍讀到的都是 1。而 SDA 沒人驅動時，會被上拉電阻維持在高電位（邏輯 1）。所以**全 FF = slave 一直保持沉默**。

## 第三關：沉默的 slave，一連串被推翻的假設（v10–v14）

這一關是整趟最長的歧路。slave 收到請求卻不吐資料，到底為什麼？一個個假設試過去：

**假設 A：資料還沒就緒，要加延遲。** 這靈感來自一個論壇案例——TI 的 TMP117，工程師遇到「slave ACK 了位址、資料階段卻沉默」，解法是「先送指標、等一下、再讀」。
→ **v10** 用 SW 開關一次測四種：純讀 / 加延遲 / 讀完寫 INT_ACK / 兩者都加。**全部還是 FF。**（但使用者觀察到：有延遲的版本，INT 在讀完會被釋放——這是個有用的副線索。）

**假設 B：這顆不用先寫暫存器位址，直接讀就好。**
→ **v11** 直接讀（START → devR → 讀 9 byte → STOP）。**還是 FF。** 這裡有個誠實的插曲：我看全景波形時，誤把一段 SDA 跳動當成「slave 在送資料」；使用者把波形**放大**後真相大白——那些跳動全是 master 自己在送位址，一進資料階段 SDA 就死在高電位。我判讀錯了，當場認錯。放大圖也順帶證明：slave 對「直接讀位址」是 **NACK**。

**假設 C：晶片開機卡在 bootloader（開機載入）模式，要先送「退出命令」喚醒它。** 這條路最深、最像、最後也最徹底失敗：
- **v13**：送 gen4 的退出命令 `{0xFF,0x01,0x3B,...}`。中間插了一段經典的「被儀表板騙了」——LEDG3（代表初始化完成）死活不亮，我一度以為狀態機卡死，還去「修」了一個計數器 bug。結果真正的兇手是**另一顆 AI（Gemini）幫忙抓到的**：那行點燈程式碼 `oREG_GESTURE={3'b001,1'b0,init_done,disp_sel}` 只有 7 個 bit 卻塞進 8 bit 的暫存器，把 `init_done` 擠到了 bit2，而 LED 讀的是 bit3——所以初始化其實早就跑完了，是燈號接錯位。（更糗的是我第一次修還差點再犯同樣的位寬錯。）燈修好後，SignalTap 顯示命令完整送出、slave 每個 byte 都 ACK，但**座標還是 FF**——格式合法、內容不對。
- **v14**：查到 gen3 的正確值（退出命令的關鍵 byte 是 `0xA5`，不是 gen4 的值），而且不是送單一命令，是一整套開機序列：**soft reset → 退出 bootloader → sysinfo mode → operate mode**。因為環境裡沒有 iverilog，改用 **Python 把狀態機實際送上線的 byte 序列逐筆重放驗證**（這比 iverilog 更直接打中前幾版的計數錯位）。序列一字不差地送出去了——**還是全 FF。**

**這是整場最大的反轉：** 一整套官方 gen3 cyttsp 開機序列完整跑完、slave 也都 ACK，卻一個座標都讀不到。唯一的解釋是——**這條 cyttsp 路線根本不對。** CY8CTMG120 是 PSoC，Terasic 在上面燒的是**自己的客製韌體**，不是 Cypress 標準 TrueTouch；真正的 I2C 協定鎖在加密 IP 裡。查 VEEK-MT 手冊也確認：手冊只記載「加密 IP 解碼後的暫存器介面」，晶片端的原始協定刻意藏起來。

> 重點修正：很多介紹會把「查 Linux cyttsp 驅動原始碼」講成破關關鍵。**事實相反——它是這趟最大的死路。** 從 v13 到 v14、好幾天的工，全花在一個對這顆客製晶片不適用的協定上。

## 第四關：別再猜了，去量——掃描器掃出 0x08（v15–v17）

反轉之後的覺悟：**我們從頭到尾，從沒在自己的板子、跑自己的程式時，親手量過「晶片到底有沒有 ACK 我們」。** 那個 0x24 是別的設定下的外部掃描器報的，從來沒被驗證。整整 14 版，都建立在這個沒驗證的地基上。

- **v15**：把晶片的 ACK 回應**直接接到 LED**（接到輸出才不會被 Quartus 當無用訊號優化掉），連續輪詢。結果：代表「位址被 ACK」的兩顆燈（**LEDG7=寫位址被 ACK、LEDG3=讀位址被 ACK**）**從沒亮過**——晶片對我們這支 master，連位址都沒 ACK。
- **v16**：把 FPGA 改寫成 **I2C 掃描器**（等同 Linux 的 `i2cdetect`），逐一對 0x00～0x7F 所有位址「敲門」，看誰回 ACK。同時加一顆**心跳燈**（LEDG7 固定節奏閃，只要時脈進得來、模組活著就一定閃），徹底分開「模組到底有沒有在跑」和「掃描結果」兩件事；HEX 這版的意義改成 **HEX7HEX6=最後一個回 ACK 的位址、HEX1HEX0=這一輪總共幾個位址 ACK**。結果：心跳正常（模組活著），但掃描結果**隨機亂跳**、快到手機 0.5 倍速都抓不住。
- **v17**：亂跳代表 ACK 取樣卡在訊號臨界值。對策——**降速 +「連續 4 次都 ACK 才算數」的一致性過濾**。這裡的「速度」指的是 **I2C 時脈（SCL 那條線）的頻率**——也就是背景章那個「節拍器」每秒打幾下，決定 bit 在線上傳多快。標準 I2C 跑 100kHz（每秒十萬拍）；**降速就是把節拍器打慢**，讓訊號有時間穩定、也給會壓住時脈的晶片喘息空間。SW[0]=0 是快（100kHz）、=1 是慢（約 4kHz，慢了約 25 倍）。結果決定性：**慢速下 HEX 穩定顯示 `08000001`**（位址 = 0x08、穩定 ACK 數量 = 1）。而且 INT 線（LEDG0）**只在慢速時狂閃**——晶片真的在回應我們。

**真正的位址是 0x08，不是 0x24。我們對著沒人的門牌喊了 15 版。**

## 第五關：時脈延伸之戰——把 SCL 改開漏（v18–v19，真正的轉捩點）

- **v18**：用 SW 一次測完「位址 × 速度 × 讀法」的矩陣（**SW0=速度快/慢、SW1=位址 0x08/0x24、SW2=直接讀/指標讀**，撥一撥就換組合，不必重燒）。關鍵對照組——對著**空的 0x24** 讀，得到**穩定的 FF**（不抖）。這一格證明了兩件事：**(1)** 上拉把 SDA 拉高完全沒問題（否則連空位址都會抖）→ 推翻「上拉太弱」；**(2)** 0x08 的閃爍不是線路問題，而是**那顆晶片在回應時做了某件事打亂我們**。
- **診斷：Clock Stretching。** PSoC 型晶片收到位址後常會**把 SCL 壓低**（時脈延伸）來爭取時間準備資料，等於對 master 喊「等我一下」。但我們的 master 有個一直沒注意的問題——`assign I2C_SCLK = scl;`，**SCL 是推挽（push-pull）輸出、被我們主動驅動高**。當晶片想壓低 SCL，我們卻硬推高，**兩邊電位打架**，master 照自己的節奏往下跑、讀到亂掉的 bit。這完美解釋了「大部分 FF、偶爾蹦出 A/E/數字、整個在抖」。
- **v19 修正：** 把 SCL 改成正確的**開漏（open-drain）**——master 只能釋放或拉低，拉高後**要先確認線真的高了**才往下走；晶片壓著就乖乖等它放手。這需要 **camera.v 改一行**：`TOUCH_I2C_SCL` 從 `output` 改成 `inout`（因為要能讀回 SCL 才知道晶片有沒有壓著它）。
- **結果：** 代表「偵測到時脈延伸」的燈（**LEDG2=stretch_seen**）**長亮**（證實晶片真的一直在壓 SCL），HEX 第一次出現**會隨觸控改變的真實資料**（88/23/C4/11，此時 HEX 仍是輪播顯示各暫存器的原始位元組）。**通訊終於打通了。**

> 這才是整個專案的轉捩點——不是 bootloader 命令，而是「承認 slave 也有發言權（會壓住時脈），把 SCL 從硬推改成開漏並等它放手」。

---

## 第六關：對齊、握手，與「拔電才解卡」（v20–v23）

通訊通了，但只有第 0 號暫存器（觸控狀態：沒碰=0x01、碰=0x80）有資料，座標暫存器全是 FF。

- **v20**（暫存器逐一檢視器，畫面凍住不輪播；**SW[3:0]=選看第幾號暫存器、SW[4]=直接讀/指標讀**，HEX 則是 **HEX7HEX6=暫存器編號、HEX1HEX0=該暫存器的值**）發現：改用 **pointer read**（讀之前先寫暫存器指標 0x00，強制從第 0 號開始）後，某個座標 byte 會**隨手指位置變化**（左上 3F → 右下 6F）。所以**對齊**是個要素。
- **握手（handshake）：** 第 0 號暫存器碰螢幕時 = 0x80，最高位 bit7=1，這是 Cypress 的「新資料就緒」旗標。晶片準備好一筆座標 → 把 bit7 設 1 → **等主機回應（把 bit7 反相、即 `rx0^0x80` 寫回第 0 號暫存器）→ 才會放出下一筆**。沒回這個握手，晶片就卡住不更新。
- **使用者的關鍵發現——拔電才解卡：** 重燒 FPGA **不會**重置觸控晶片，但**拔掉整塊板的電源會**。連續二十幾版對它灌半成品 I2C，很可能把這顆 PSoC 搞進「卡死」狀態；拔電讓它回到乾淨狀態，座標就冒出來了。這也解釋了為什麼之前間歇性才讀到——沒持續正確握手，它讀一筆又卡住。
- **一段必須誠實寫下的插曲——上拉電阻：** 過程中我**好幾次建議去焊外部上拉電阻**，把「讀不穩」推給硬體。是**使用者打臉**：「學長同樣硬體、沒焊電阻就能動，代表一定能用韌體解決。」我**收回建議、承認那是退縮**。觸控面板本身爛（要用力按幾下才有反應）是它天生的，跟上拉無關；板上的 TXS0104 電平轉換器（把 FPGA 端的 2.5V 與觸控端的 3.3V 互轉）+ FPGA 內部弱上拉本來就夠。**這一筆是人的領域知識，糾正了 AI 的錯誤判斷。**
- **v23**：把 **pointer read + 每筆讀完握手**兩件事固定綁在一起——正是拔電後讀到座標的組合。持續正確握手後，晶片**不再需要反覆拔電**。

---

## 第七關：破解座標格式（v24）

用「按住四個角」測出的乾淨資料推導。座標最大到 800 多，一個 8 位元的位元組（最多只到 255）裝不下，所以一個座標**拆成兩個位元組：高位元組 + 低位元組**；而「**大端（big-endian）**」就是把高位元組排在前面。對照四角數值：

- **X = {rx3, rx4}**：rx3 是 X 的高位元組、rx4 是低位元組。左上≈49、右上/右下≈753–755 → 對得上 800 寬。
- **Y = {rx5, rx6}**：rx5 是 Y 的高位元組、rx6 是低位元組。上≈33、下≈408 → 對得上 480 高。

繞了一大圈，座標格式**竟然真的是標準 cyttsp gen3 的暫存器排列**——但要讀到它，**位址 0x08、I2C 時脈慢到 1kHz、開漏 SCL + 處理時脈延伸、pointer read 對齊、每筆握手**，五項缺一不可。（為什麼要慢到 1kHz：快了就跟時脈延伸對打、訊號邊緣也來不及穩；掃描時用的 4kHz 雖然掃得到位址，但讀座標時後段的位元組還是會掉，再降到 1kHz 才乾淨。）

使用者還順手做了第二重驗證：橫掃整個寬度時，低位元組「倒數約 3 次」（X 範圍 706÷256≈2.76）、縱掃「繞 1 次」（Y 範圍 375÷256≈1.5）——行為完全吻合。

中間還清掉兩個小坑：HEX 一開始只顯示了**低位元組**（缺高位，導致座標「進位繞圈」看不出真正範圍），改成顯示完整 `XXX00YYY` 才對（**HEX7–HEX5=完整 X 的三個 16 進位字、HEX2–HEX0=完整 Y、中間 `00` 當分隔**）；以及兩個編譯錯誤（`SEG_output` 連續賦值漏了 `assign`、`rstn` 沒宣告改用 `KEY[0]`）。

## 第八關：手指偵測，與最後一個 bug（收尾）

座標讀到了，但**晶片會鎖住放開前的最後座標**。所以**不能用「座標有效/有變化」來判斷手指在不在**（放開後座標還在）。乾淨的「手指在/不在」訊號是 **INT 線**（`!TOUCH_INT_n`，就是 LEDG0）——實測按下亮、放開熄，確認無誤。

最後一個 bug 也卡在這裡：負責回答「現在有沒有人碰」的 `TOUCH_DETECT` 模組，原本用「座標有沒有變」判斷（在這顆晶片上是壞的），後來改讀 INT 線、但用了**對稱式去彈跳**（要 INT 連續穩定一段時間才認定）。偏偏這片弱面板的 INT 會**間歇抖動**，計數一直被打斷重置，導致觸控訊號**永遠到不了 1**——表現出來就是「動畫完全不觸發」。改成 **可重觸發的單擊延時（retriggerable one-shot，約 150ms）**：一偵測到手指就立刻拉高，短暫抖動被保持期蓋過，放開後才熄。改完——按住任一處時 **LEDG6（=touch_detect，這版專門接出來驗證手指偵測有沒有修好）** 會亮，**動畫也終於隨著手指作動。收工。**

## 工具與資料總整理：我們用了什麼、為什麼

這趟用的工具不多，但每個都關鍵：

**Verilog**——描述 FPGA 電路的語言；整個 I2C 驅動、座標解碼都是用它刻的。
**Quartus + SignalTap**——Quartus 把 Verilog 編譯/燒錄；內建的 SignalTap 邏輯分析儀能抓 FPGA 內部實際運行的訊號波形。**免費、看真實硬體**，前期幾乎每個關鍵判斷（v8 時序 bug、v9 全 FF、ACK 狀態）都靠它。
**Python（取代 iverilog）**——環境裡沒有 iverilog，所以改用 Python 把狀態機「實際送上 I2C 線的 byte 序列」逐筆重放驗證，專打前幾版的 off-by-one 計數錯位。
**LED 當除錯儀表**——把 ACK 回應、時脈延伸偵測、心跳直接點在 LED 上。SignalTap 設定容易騙人（觸發條件抓錯就看不到該看的），把關鍵訊號綁到 LED 反而一眼就懂。**「有沒有 ACK」永遠是 I2C 除錯第一步。**
**I2C 掃描器（i2cdetect 概念）**——把 FPGA 變成掃描器逐一敲門，讓硬體自己說出晶片在哪個位址。這是找出 0x08、推翻 0x24 的關鍵手法。
**SW 指撥開關**——板上實體開關，燒一次就能現場切換不同策略/速度/讀法，不用反覆重編譯。

**參考的資料（回答「到底站在哪些公開資料上」）：**

1. **I2C 標準協定知識**——START/STOP、ACK/NACK、7-bit/8-bit 位址，以及**最關鍵的 clock stretching 與 open-drain**。沒有這層底層知識，第五關的時脈延伸根本解不開。
2. **Cypress 官方 Linux 驅動原始碼**——gen4 的 `cyttsp4_core.c` 與 gen3 的 `cyttsp` / `cyttsp.h`。**最後證明對這顆客製晶片是死路**（bootloader 命令完全沒用），只有座標格式「碰巧」吻合 gen3。
3. **Terasic VEEK-MT 手冊 + DE2-115 使用手冊**——確認官方 IP 是加密的、只記載解碼後的暫存器介面，逼我們走自己手刻的路。
4. **NIOS 原廠程式碼**——透露讀資料前會先讀「資料數量」暫存器、之後寫 INT_ACK，給了握手機制的線索。
5. **TI TMP117 論壇案例**——「slave ACK 了位址 ≠ 資料就緒」的靈感來源，引出加延遲那一串測試。
6. **i2cdetect（Linux 工具）概念**——掃描器的設計藍本。

## 從這趟旅程學到的工程原則

1. **交接文件是線索，不是聖經。** 0x24 從沒在這塊板量過，卻被當地基用了 15 版。真正能信的是你親手量到的。
2. **官方原始碼不等於你的晶片。** 整條 cyttsp 路線之所以全盤皆輸，是因為 Terasic 的客製韌體 ≠ 原廠 TrueTouch。把別人的驅動當聖經會害你在錯前提上鬼打牆。
3. **動手蓋之前，先量地基。** 「讓硬體自己說話」（掃描器）才是真正的解鎖點——在那之前的努力全在猜。
4. **標準寫法有它的前提。** 推挽 SCL 是一般 FPGA I2C 的直覺寫法，但它跟「會壓住時脈」的 slave 對打。失靈時要換的是方法，不是參數。
5. **發現自己一直在替一個訊號打補丁時，回頭質疑前提。** 手指偵測那關——問題不在補丁不夠，而在一開始就拿錯訊號（該用 INT，卻用座標）。
6. **最便宜的修法常常是「別動硬體」——但也要願意被打臉。** 上拉電阻那段是 AI 連續建議錯、被人的領域知識糾正。誠實面對自己的判讀錯誤（誤讀波形、算錯位寬）和別人（包括另一個 AI）抓到的 bug，比死撐有用。
7. **理性 + 免費工具能走很遠。** SignalTap + LED + Python 模擬，沒買邏輯分析儀、沒焊任何電阻，硬是把一顆加密黑箱晶片的座標撬了出來。

## 結語

從「檔案打不開」到「點圖形觸發動畫」，中間沒有一步是天上掉下來的。24 個版本、好幾條走到底的死路（猜錯位址 15 版、cyttsp 整條白走、誤讀波形、建議錯解法），每一個錯的猜想都被誠實地驗證、誠實地丟掉——剩下的才是能動的那一版。

如果你是剛入門的讀者，希望你帶走的不只是「觸控螢幕怎麼接」，而是這件更重要的事：**在迷霧中前進、不斷推翻自己的方法，本身是可以學會、而且到處都用得上的。**

### 附錄：名詞小辭典

| 名詞 | 白話解釋 |
|---|---|
| **FPGA** | 可以「重新接線」的晶片；用 Verilog 描述電路，它就長成那個電路。 |
| **PSoC** | 內含微控制器的可程式晶片。本案觸控 IC 是 PSoC，行為取決於裡面燒的韌體（Terasic 客製），所以原廠手冊不適用。 |
| **觸控控制器** | 把電容變化換算成 X/Y 座標的小晶片，本案是 Cypress CY8CTMG120-56。 |
| **I2C** | 兩條線（SDA 資料、SCL 時脈）的晶片間通訊協定，有主從與位址之分。 |
| **ACK / NACK** | 從機在第 9 拍把 SDA 拉低 = ACK（收到）；維持高 = NACK（沒人理）。 |
| **位址（address）** | 一個 7 位元數字；送出的第一個位元組前 7 bit 是位址、最後 1 bit 是讀/寫。本案正解 7-bit 位址 0x08（線上為 0x10 寫 / 0x11 讀），被誤認成 0x24 達 15 版。 |
| **clock stretching（時脈延伸）** | 從機需要時間時，把 SCL 壓低要主機等一下。本案的隱藏殺手。 |
| **I2C 時脈頻率（速度）** | SCL 線每秒打幾拍，決定資料傳多快。標準 100kHz；本案因時脈延伸 + 面板訊號弱，要慢到 1kHz 才穩。 |
| **open-drain / push-pull** | 開漏：線只能被拉低、要全體放手才升高（多方可共用、可互相喊停）。推挽：主動驅動高或低。SCL 用推挽會跟想壓低時脈的晶片打架。 |
| **big-endian（大端）** | 一個多位元組數值，把高位元組排在前面。本案 X={rx3 高, rx4 低}、Y={rx5 高, rx6 低}。 |
| **pointer read（指標讀）** | 讀之前先寫暫存器指標（0x00），強制從已知位置開始讀，解決對齊問題。 |
| **handshake（握手）** | 讀完把 `rx0^0x80` 寫回第 0 號暫存器，向晶片「簽收」，它才放出下一筆；不做會卡死。 |
| **INT（中斷線）** | 觸控晶片用來說「現在有手指」的專線（拉低代表有觸控）。 |
| **latch（鎖住）** | 數值被保留住不更新。本案手指放開後座標被鎖住，所以不能用座標判斷手指在不在。 |
| **retriggerable one-shot（可重觸發單擊延時）** | 一觸發就維持一段固定時間，期間再被觸發就重新延長——本案手指偵測去抖的正解。 |
| **SignalTap** | Quartus 內建的免費邏輯分析儀，能抓 FPGA 內部實際運行的波形。 |
| **i2cdetect / I2C 掃描器** | 逐一對所有位址敲門、看誰回 ACK 的工具/手法。本案靠它掃出真正的 0x08。 |
| **bitstream** | 編譯後燒進 FPGA 的設定檔；不能反編譯回 Verilog。 |

## 附錄：各版本 SW / HEX / LEDG 對照速查

因為這些都是除錯版，同一顆開關／顯示器／燈在不同版本意義一直變——這張表把每一版「當下」的意義集中起來方便回查。表中**「同基準」**指沿用最初的顯示約定：HEX 輪播顯示讀回的位元組對（`HEX7HEX6` 一個位元組、`HEX1HEX0` 一個位元組、中間 `0000` 分隔，全 FF 時就是 `FF0000FF`），LEDG7=模組運作中、LEDG2:1=輪播組號、LEDG0=INT(`!TOUCH_INT_n`)。

| 版本 | 這版在做什麼 | SW（開關） | HEX（顯示） | LEDG（燈號） |
|---|---|---|---|---|
| **v1–v9** | 建立 I2C 通訊；v8 抓到 SDA/SCL 競態、v9 改 5-phase 修好（仍全 FF） | 未特別使用 | 同基準（全 FF = `FF0000FF`） | 同基準（LEDG7 運作中、LEDG2:1 組號、LEDG0 INT） |
| **v10** | 測「加延遲／INT_ACK」能否讓 slave 吐資料（全失敗） | `SW1:0` 讀取策略：00 純讀／01 加延遲／10 讀後 INT_ACK／11 兩者 | 同基準 | 同基準（靠 LEDG0 觀察到「延遲版 INT 會被釋放」） |
| **v11** | 測「直接讀 vs 先寫指標再讀」（全失敗） | `SW1:0` 讀法：00 直接讀／01 寫指標再讀／10 直接+INT_ACK／11 指標+INT_ACK | 同基準 | 同基準 |
| **v12**（未燒） | 想調取樣相位（後判定方向錯，沒燒） | `SW1:0` 取樣相位 | 同基準 | 同基準 |
| **v13** | 送 gen4 bootloader 退出命令（失敗） | `SW0` 是否送 ldr_exit：0 跳過／1 送 | 同基準 | **`LEDG3`=init_done**（著名位寬 bug：本應亮卻被接到看不到的 bit） |
| **v14** | 跑完整 gen3 開機序列（失敗，cyttsp 路線就此判死） | `SW0` 是否跑序列、`SW1` 讀後握手（00 跳過／01 完整序列／11 序列+握手） | 同基準 | `LEDG7`=init 跑完、`LEDG3`=序列真的跑過 |
| **v15** | 第一次把「晶片有沒有 ACK 我們」點到燈上（兩燈全沒亮） | `SW0` 讀法：0 寫指標讀／1 直接讀 | 輪播 rx 位元組 | `LEDG7`=寫位址 0x48 被 ACK、`LEDG3`=讀位址 0x49 被 ACK、`LEDG5`=每次輪詢脈衝（太短看不到）、`LEDG0`=INT |
| **v16** | 把 FPGA 變 I2C 掃描器，掃全部位址 | 未用（掃 0x00～0x7F） | `HEX7HEX6`=最後一個回 ACK 的位址、`HEX1HEX0`=這輪 ACK 數量 | `LEDG7`=心跳(~1.5Hz)、`LEDG3`=這輪有任何位址 ACK |
