## 2. 實體層 / 匯流排設定

### 2.1 接線與電壓
- **SDA**（資料）、**SCL**（時脈）兩條線；外加一條 **INT（中斷，低電位有效）**。✅
- FPGA 側 2.5V，觸控側 3.3V，中間靠板上 **TXS0104 電平轉換器**自動互轉。寫驅動時**不需要**自己改 IO 電壓標準。✅〔測〕
- **上拉:** 本板只靠 FPGA 內部弱上拉(~25kΩ)+ TXS0104 即可,**毋須外接電阻**。
  - 🔶 註:若想跑更快(>4kHz),外接 2.2k–4.7kΩ 到 3.3V 會讓邊緣更乾淨;但**慢速下完全不必**。這是取捨,不是必需。

### 2.2 位址（最容易踩的坑）
- 7-bit 位址 = **0x08**。✅〔測〕
- I2C 把位址當「第一個位元組」送出:前 7 bit 是位址、最後 1 bit 是 R/W(0=寫、1=讀)。所以:
  - 寫 = `0x08 << 1 | 0` = **0x10**
  - 讀 = `0x08 << 1 | 1` = **0x11**
- ⚠️ 注意「7-bit vs 8-bit 位址」表示法混淆:若別處文件寫的是「8-bit 位址」,數字會差一倍。本規格一律用 **7-bit = 0x08**。

### 2.3 速度
- **目標 ~1 kHz**(SCL 每秒約 1000 拍)。✅〔測〕
- 為什麼這麼慢:見 §7。簡述——快了會跟晶片的時脈延伸對打、且這片面板訊號邊緣爬升慢。

### 2.4 SCL 必須開漏 + 處理時脈延伸（本規格最關鍵的一條）
這顆是 PSoC(內含 MCU),**收到位址後會主動把 SCL 壓低**(時脈延伸)來爭取時間準備資料。✅〔測〕

因此主機端**必須**:
1. SCL 用**開漏**:主機只能「拉低」或「釋放」,**不能主動把 SCL 推高**。
2. 把 SCL 拉高後,**先確認線真的變高了**(因為晶片可能壓著)**才繼續**;晶片壓著時就乖乖等它放手。

> 若主機用推挽(push-pull)硬推 SCL 高,會跟想壓低的晶片**電位打架**,讀到的位元就會亂掉(表現為大部分 FF、偶爾蹦出隨機值、整個在抖)。這是前 18 版失敗的真正原因。

### 2.5 INT 中斷線
- **低電位 = 現在有手指**;放開後回高。✅〔測〕
- 這條線是「手指在不在」唯一可靠的來源(理由見 §6)。

## 3. 讀取封包 / 暫存器對照（9 位元組）

每次讀取會連續拿到 9 個位元組,本文件稱 **rx0 … rx8**(rx = receive)。實測**只有 rx0–rx6 帶有意義**,rx7/rx8 觀察到都是 FF/無資料(這顆的觸控格式很精簡)。

| 位元組 | 意義 | 觀察到的值 / 範圍 | 可信度 |
|---|---|---|---|
| **rx0** | **狀態 / 握手位元組**。bit7 = 「新資料就緒 / 有觸控」 | 沒碰 = `0x01`；單指 = `0x80`；多指或滑動偶爾 `0xC0` | ✅〔測〕；bit7 慣例〔公〕 |
| **rx1** | 不明、不穩定（偶爾瞬間出現 0x3F/0x6F/0x0d，無法穩定解讀） | 多為 FF | ❔ |
| **rx2** | **觸控點數**（低 4 位 = 幾根手指） | 單指時低位元少；三指時出現 0x38/0x78 | 🔶〔公/測〕 |
| **rx3** | **X 高位元組**（範圍受限，因 X≤800） | 只在 `00–03` 之間 | ✅〔測〕 |
| **rx4** | **X 低位元組** | 左右滑會劇烈變化 | ✅〔測〕 |
| **rx5** | **Y 高位元組**（範圍受限，因 Y≤480） | 只在 `00–01` 之間 | ✅〔測〕 |
| **rx6** | **Y 低位元組** | 上下滑會劇烈變化 | ✅〔測〕 |
| **rx7, rx8** | 無觀察到有意義資料（多為 FF；可能是填充） | FF | ❔ |

> **怎麼自己驗 rx3–rx6 是哪個軸的:**（這是當初確認的方法，你也能複現）
> - 手指**只左右滑**:會劇烈變的低位元組就是 **X 低(rx4)**;同時只在 00–03 跳的就是 **X 高(rx3)**。
> - 手指**只上下滑**:會劇烈變的就是 **Y 低(rx6)**;只在 00–01 跳的就是 **Y 高(rx5)**。

## 4. 座標解碼

### 4.1 公式（大端 / big-endian：高位元組在前）
座標值最大到 800/480，一個 8-bit 位元組(最多 255)裝不下,所以拆成「高位元組 + 低位元組」兩格,且**高位元組在前**:

```
X = (rx3 << 8) | rx4      // rx3 = 高位元組(只用低 2 bit), rx4 = 低位元組 → 約 0–800
Y = (rx5 << 8) | rx6      // rx5 = 高位元組(只用低 1 bit), rx6 = 低位元組 → 約 0–480
```

### 4.2 實測範圍（你校正時可拿來對）✅〔測〕
- **X:** 最左 ≈ **49** → 最右 ≈ **755**（對得上 800 寬）
- **Y:** 最上 ≈ **33** → 最下 ≈ **408**（對得上 480 高）
- 🔶 註:Y 似乎在 ~408 附近就到頂(可能是面板感應上限,或本板某角實體偏弱),不一定能讀到接近 480。把這當「可能的天花板」,自己量到再修。

### 4.3 實測「測試向量」（最有用的驗證資料）✅〔測〕
按住四個角實際讀到的原始位元組 → 解出的座標。**拿你自己的解碼器跑這幾組,對得上就代表解碼對了:**

| 位置 | rx3:rx4（X 高:低） | → X（十進位） | rx5:rx6（Y 高:低） | → Y（十進位） |
|---|---|---|---|---|
| 左上 | `00 : 31` | **49** | `00 : 21` | **33** |
| 右上 | `02 : F1` | **753** | `00 : 55` | **85** |
| 右下 | `02 : F3` | **755** | `01 : 98` | **408** |

（驗算範例:右下 X = 0x02F3 = 2×256 + 243 = **755**；Y = 0x0198 = 1×256 + 152 = **408**。✓）

## 5. 驅動序列（核心：要做哪些動作才驅動得了）

### 5.1 重置（卡死時才需要）✅〔測〕
- **重燒 FPGA／重置主機，並不會重置這顆觸控晶片**;只有**把整塊板的電源拔掉再上電**才會。
- 為什麼重要:對它灌過很多版半成品 I2C 後,這顆 PSoC 可能進入卡死狀態,讀到的永遠是 FF。**拔電一次**讓它回乾淨,是排除「明明接對卻全 FF」的第一招。

### 5.2 每一輪讀取（語言無關的步驟）

```
重複（輪詢 / 或在 INT 拉低時）:

  1. 指標讀（pointer read，務必）:
       START
       送 0x10 (devW)          ; 寫位址
       送 0x00                 ; 把暫存器指標指到第 0 號
       repeated-START
       送 0x11 (devR)          ; 讀位址
       連續讀 9 個位元組 → rx0..rx8（讀最後一個 byte 時回 NACK）
       STOP

  2. 檢查 rx0 的 bit7:
       若 (rx0 & 0x80) == 0  → 這輪沒有新觸控資料，跳過解碼

  3. 解碼座標:
       X = (rx3 << 8) | rx4
       Y = (rx5 << 8) | rx6

  4. 握手（每筆讀完，建議務必做；理由見下）:
       START
       送 0x10 (devW)
       送 0x00                 ; 指到第 0 號暫存器
       送 (rx0 XOR 0x80)       ; 把 bit7 反相寫回 → 等於向晶片「簽收」
       STOP

  ※ 全程 SCL 開漏、遇到晶片壓低 SCL 要等它放手（見 §2.4）
```

### 5.3 關於「指標讀」與「握手」的誠實說明
- **指標讀(寫 0x00 再讀):** ✅ 確實需要。雖然晶片多半會在每個 START 自動把指標歸零,但**明確先寫 0x00 才讓對齊穩定**;少了它,讀到的位元組會錯位/對不到座標。
- **握手(寫 rx0^0x80 回 reg0):** 🔶 這條要講清楚。
  - bit7 = 「新資料就緒」是 Cypress 這類晶片的慣例〔公〕:晶片備妥一筆 → 把 bit7 設 1 → 等主機「簽收」(把 bit7 反相寫回)→ 才放出下一筆。
  - **誠實的實測經驗:** 在**剛拔電 + 指標讀**的乾淨狀態下,座標其實**不做握手也會先冒出來**;真正一開始擋住我們的是「對齊(指標讀)」+「後段位元組訊號偏弱」。
  - **但**:要**持續、穩定**地連續更新,**握手是建議做的**——少了它,晶片讀著讀著會卡住(回到全 FF,得再拔電)。最終能動的版本是「**指標讀 + 每筆握手**」綁在一起,之後就不必再反覆拔電。
  - 結論:**想要長時間穩定運作,就把握手做上。** 想先最小驗證「讀得到座標」,可以先省略握手、靠剛拔電的狀態快速確認方向。

## 6. 手指偵測（在不在）

- **不要用「座標有效／有變化」判斷手指在不在。** ✅〔測〕原因:**晶片會鎖住(latch)放開前的最後一筆座標**——手指離開後,座標暫存器還停在舊值,看起來像「還按著」。
- **正解:讀 INT 線**(低電位 = 有手指,高 = 沒手指)。
- **去彈跳要用「可重觸發單擊延時(retriggerable one-shot)」,不要用對稱式去彈跳。** ✅〔測〕
  - 這片面板的 INT 會**間歇抖動**;對稱式去彈跳(要 INT 連續穩定一段時間才認定)會被抖動一直打斷、永遠認不到「按下」。
  - 可重觸發單擊:一偵測到就立刻判定「有手指」,並維持一段固定時間(實測 **~150ms** 好用);期間若再被觸發就重新延長,放開後過了保持期才判定「沒手指」。短暫抖動會被保持期蓋過。

## 7. 時序與已知地雷（為什麼要這樣做）

| 現象 / 規則 | 說明 | 可信度 |
|---|---|---|
| **必須慢到 ~1kHz** | 快速會(1)跟時脈延伸對打、(2)這片面板 SDA 邊緣爬升慢,取樣卡在臨界值 → 隨機亂跳。掃位址用 4kHz 還行,但**讀座標**時 4kHz 後段位元組會掉,要降到 1kHz 才乾淨。 | ✅〔測〕 |
| **100kHz（標準速度）直接失敗** | 在沒有外接上拉時,標準速度下連位址 ACK 都取樣不穩。 | ✅〔測〕 |
| **晶片壓 SCL（時脈延伸）** | 收到位址後會壓低 SCL 要主機等;主機必須開漏 + 等放手(§2.4)。 | ✅〔測〕 |
| **重燒不重置、拔電才重置** | 主機重燒/重置不影響觸控晶片狀態;卡死只能拔電解。 | ✅〔測〕 |
| **座標被鎖住(latch)** | 放開後座標停在最後一筆 → 用 INT 判斷手指,別用座標。 | ✅〔測〕 |
| **面板天生偏弱** | 這片要稍微用力按才靈敏、某角落較差;屬硬體特性,不是協定問題,也跟上拉無關。 | ✅〔測〕 |

## 9. 最小實作檢查清單（照做就能動）

照順序確認,每一項都做到就應該讀得到座標:

1. ☐ I2C 主機用位址 **0x08**(線上寫 0x10 / 讀 0x11)。
2. ☐ SCL 設為**開漏**;拉高後**等線真的高了**才往下(處理時脈延伸)。
3. ☐ SDA 開漏;**不必**外接上拉。
4. ☐ I2C 速度降到 **~1kHz**。
5. ☐ 若一直讀到全 FF,先**拔板子電源再上電**一次。
6. ☐ 每輪讀取:先 **寫指標 0x00**,再讀 9 個位元組。
7. ☐ 檢查 **rx0 bit7**;為 1 才解碼。
8. ☐ `X = (rx3<<8)|rx4`、`Y = (rx5<<8)|rx6`。
9. ☐ 每筆讀完寫回 **rx0 XOR 0x80**(握手,持續運作必做)。
10. ☐ 手指在不在 → 看 **INT 線**(低=有),搭配 **~150ms 可重觸發單擊**去彈跳。
11. ☐ 用 §4.3 的**四角測試向量**驗證你的解碼正確。
